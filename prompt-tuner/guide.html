What Changed

这次稳定化不是只搬一个旧脚本，而是把它补成“可审核、可演示、可复用”的毕业形态。

01

统一触发口径

“优化 prompt”“做 prompt 回归测试”“处理 cases.yaml”“TDD for prompts” 都会命中这个 skill。

02

补本地检查模式

新增 python3 tuner.py --check，只验证结构，不打模型接口，适合审核与快速巡检。

03

补齐稳定交付物

`SKILL.md`、`.env.example`、README、guide 页面、稳定 runner 一次补齐。

Use It In Two Modes

审核时跑本地检查，真正调 prompt 时跑全量回归。这是这次改造最关键的边界。

模式 A: 本地结构检查

TDD Workflow

这套流程是稳定版 skill 的核心，不是“想到哪改到哪”。

Check
先确认基线先跑 --check，再看是否需要真实回归测试。
Red
先补失败 case先把新的 bad case 写进 cases.yaml，让问题可重复。
Green
再改 prompt修改 prompt.txt，直到所有 case 重新变绿。
Record
最后记版本同步更新 prompt.txt 首行版本号和 CHANGELOG.md。

Input / Output

审核时最重要的是看边界，不是盯着实现细节。

Input

  • prompt.txt：待调优的系统提示词
  • cases.yaml：Golden Dataset
  • .env：provider、model、API key

Output

  • 终端里的 pass/fail 表格
  • 失败 case 的 raw actual 结果
  • 版本更新后的 prompt.txt 和 CHANGELOG.md

Review Checklist

这就是审核员需要看的最小口径。

文档检查

  • SKILL.md 是否说清何时触发
  • 输入/输出边界是否明确
  • 有没有不依赖 key 的最小验证命令

执行检查

  • python3 tuner.py --check 能否通过
  • `.env.example` 是否足够让人配置 provider
  • 完整回归命令路径是否清晰
