# 会话摘要（mirasim-session-digest）

给一个人（**摘要对象**）出会话摘要，交给**请求人**（谁要的）。两人可以是同一个人。

脚本：本文件旁边的 `scripts/digest.py`（下文写作 `$D`，用时换成本技能目录的绝对路径，如 `~/.mirasim/skills/mirasim-session-digest/scripts/digest.py`）。只读源会话和聊天记录，不改它们；重的命令前加 `nice -n 10`。

## 隐私边界（先读，必须守）

- **能读的范围 = 请求人的范围**：大厅、事项、会话评论、群；私信和私密群只读请求人本人在里面的。脚本已按这条过滤频道日志、任务账本和定时任务，不要绕开它自己去翻。
- 替别人出（请求人 ≠ 摘要对象）时，摘要对象的工作台会话和他私设的定时任务不读，来自请求人看不到的私信和私密群的轮次也不算，只看请求人能看到的地方。交付时 text 第一句就说明这一点。
  - 「私设的定时任务」= 这个人自己设的、没挂在请求人能看到的频道上的。挂在大厅、群或请求人在里面的私信上、为这个人跑的（例如在群里替他设的日报）照算。
- 别人私信里说的只留结论，不引原话；同一会话里别人说的轮次不写进摘要。替别人出时，摘要对象自己的原话也不引，只写意思。
- 不写邮箱、手机号、密钥、带 token 的链接（脚本在材料和并库时都会再抹一遍）。
- 摘要只交给请求人，发在他跟你说话的地方；不发群，不转给第三个人。
- md 和网页里留着会话链接（`mirasim://session/...`，在 mirasim 里点开就进原会话）和「细节线索」（消息编号、任务编号），方便请求人核查；`check` 会拦住指向他看不到的私信和群的编号。

## 第一次：init

```bash
nice -n 10 python3 $D init --user <uid 或名字> [--requester <uid 或名字>] [--days 7 | --since 'YYYY-MM-DD HH:MM'] [--dir <目录>] [--title <标题>]
```

- `--user` 摘要对象；`--requester` 请求人，不填 = 本人给自己出。名字认不出或重名时脚本会停，改用 `usr_` 开头的 uid（`~/.mirasim/chat/users/<uid>/profile.json` 里有名字）。
- 起点默认往前 7 天；`--days N` 是从现在往前推 N×24 小时，不是从那天 0 点算。第一次窗口太长会很慢，超过一个月先问请求人。
- 打印出的 `dir` 是这份摘要的目录（不填 `--dir` 时默认 `~/workspaces/session-digest/<uid>`，替别人出是 `<uid>-for-<请求人uid>`），后面每一步都要 `--dir <dir>`。
- 标签：`<dir>/config.json` 的 `tags` 是默认九个（#产品与研发 #运营与增长 #客户与支持 #内容与宣传 #数据与分析 #定价与额度 #团队与协作 #固定任务与报表 #助手怎么用，外加兜底 #其他）。标签按**摘要对象**做的事分。第一次交付时在 text 最后一句问请求人要不要改，并按这批摘要里实际出现的事给一版建议；他回了就编辑 `tags`，把 `tags_confirmed` 写成 true，之后不再问。标签 4–10 个、每个 2–8 个汉字、带 `#`。改标签只影响以后的批次，旧的事不重标。

## 每次（第一次和每天增量都一样）

1. **找新轮次**：`nice -n 10 python3 $D prep --dir <dir>`
   打印 `label`、`sessions`（这次要写的会话数）、每批的材料包 `packet` 和要写的 `out`。另外几个数只作参考：`target_messages` 是这个人历来在请求人能看的地方发过的消息数（不是窗口内的）；`rooms_skipped_for_privacy` 是请求人不在里面、整个跳过的私信和群；`candidates` 是历来跟这个人有关的会话；`others_turns_dropped` 是同会话里别人说的轮次。
   - `sessions` 为 0：跑 `python3 $D empty <label> --dir <dir>` 推进截止时间，跳到第 4 步只发一句话。
2. **写事件**：每批交给一个帮手，几批就在同一条消息里并行派（Agent 工具，general-purpose）。提示照抄：
   > 你是第 N 批，label 是 <label>。先完整读 `<技能目录>/references/writer-guide.md`，再读 `<dir>/work/packets/<label>/brief.md`（里面有你这批要读、要写的绝对路径和自查命令），然后照做。只读材料，不改别的文件，不发消息，不去翻材料以外的会话和聊天。
   没有 Agent 工具就自己按 writer-guide 一批一批写。全部交回后自己抽查：会话数对得上，正文里没有路径、消息编号、邮箱。
3. **检查并合并**：
   - `python3 $D check <label> --dir <dir>`：`problems` 非空就改对应的 out 文件再查。「看不到的地方」「缺会话」「标签不对」「状态不对」会挡住合并，必须改；其余是提醒，能改就改。
   - `nice -n 10 python3 $D merge <label> --dir <dir>`：并进底库，重出 md、网页和其余文件，打印本次新增（段数、状态分布、等这个人定的段数、标题），同时存进 `data/last-merge.json`。报「已经并过了」就是并好了，不要重并；它会把那次的新增再打一遍，写交付照用。
4. **交付**给请求人，在他跟你说话的地方（私信主线或那个话题）用 chat_reply：
   - `attachments` 放 `<dir>/<标题>.md` 和 `<dir>/<标题>.html` 两个文件。
   - `text` 两三行人话（第一次替别人出、还要问标签时可以四行）：更新到几点；新增几个会话、几段活动；最值得看的一两件，等这个人拍板的先说。不贴路径、uid、消息编号。
   - 替别人出：第一句说清「只看了你能看到的地方，X 自己工作台里的会话和私设的定时任务没读」。
   - 第一次交付且 `tags_confirmed` 还是 false：最后一句问标签要不要改（见 init）。
   - 没有新东西就只发一句「上次以来没有新的会话活动，会话摘要还是 X 月 X 日那份」，不附文件。
   - 不发群，不 @ 人。

## 每天自动增量

请求人要「每天更新」时，用 schedule_task 建一个定时任务（例如每天 06:30：`30 6 * * *`），prompt 照 `references/schedule-prompt.md` 填好 `<dir>`、技能目录和交付的 room。prompt 里必须带「会话摘要每日增量」这几个字：脚本靠它认出定时任务自己的轮次，不把它算进摘要。告诉请求人下次几点出。

## 摘要长什么样

`<dir>/<标题>.md`（底层数据）和 `<标题>.html`（从 md 生成，手机能看）：

1. 开头：更新到几点；**最新一次新增**（这次窗口里的每段活动一行：时间、标题、标签、状态）；**一眼看完**（会话数、段数、主动/自动各多少、会话怎么来的、状态分布、主题分布、等这个人定的有几段）。
2. **一、Activity Digest**：按天倒序，新的在上；分「主动的」（用户主动 + 明确派工）和「自动跑的」（自动任务 + 自动派生）。每段：时间、标题、标签、会话、运行时间、状态、证据（最多 4 条）、判断、下一检查。
3. **二、每个会话的摘要**：最近有动静的在上。每个会话：助手、会话 ID、开始时间、处理窗口、来源，下面逐件 Events：活动时间、一句话、高层总结、判断/状态、证据、下一步、标签、细节线索。

网页：搜索框、「等 X 定的」筛选、按标签筛、全部展开/收起；最近两天默认展开。

状态只有七种：已完成、进行中、中断、失败、阻塞或等待、等待验收、无新增产物。「等这个人定的」= 状态是阻塞或等待、下一步里有「等你」（本人）或「等<名字>」（匹配时不管中间有没有空格）。

## 会话从哪找（脚本已做，出问题时对照）

| 来源 | 认法 |
|---|---|
| A | 频道里这个人发的消息，助手接单卡（assist/ask）的 request 是这条 |
| B | 派单卡（dispatch）问的是这个人那条 |
| C | 这个人的消息直接点了会话（@对话） |
| D | 任务账本 `~/.mirasim/chat/assistants/dispatched.json` 里 requester 是这个人（来源频道请求人能看） |
| E | 工作台 `~/.mirasim/collab/turns.jsonl` 里是这个人说的（只在给本人出时） |
| F | 这个人设的定时任务（`~/.mirasim/schedules/` 的 setters、assistants.json 里 requester 是他）→ `runs.jsonl` 里的会话 |
| G | 「【Matrix】回复 · room#seq」且那条是这个人的 |

逐轮再判一次是谁触发的：这个人、助手按他的话派活、定时任务、自动接话算进去；续跑跟上一轮；别人的轮次只计数；同一 taskId 在多个会话里出现只算第一次。

## 目录里的东西

`config.json`（给谁、谁要的、标签）· `<标题>.md` / `.html` · `activity-digest.md` · `summaries/`（每个会话一份）· `manifest.json` · `data/store.json`（底库）、`data/state.json`（截止时间和处理过的轮次）· `work/`（材料包、事件）· `历史版/`（每次一份快照）。

- 重出网页：`python3 $D html --dir <dir>`；重出全部：`python3 $D render --dir <dir>`；看进度：`python3 $D status --dir <dir>`。
- 要从头重来：把整个 `<dir>` 挪走再 init，不要手改 store.json 和 state.json。

## 同一份摘要同时只能一处在跑

- 脚本对 `<dir>` 加了锁：另一处正在 prep / merge 时会直接停，等它跑完。
- prep 发现两小时内出过、还没并的材料包会停下，说明多半有人在跑这份摘要：不要重出，接着写那个 label 的事件再 merge。确定是自己上次半路失败、要重出，才加 `--force`。
- 每天的定时任务和手动补跑不要同时开。
