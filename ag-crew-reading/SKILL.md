# AG CREW 围读

把文章变成可回源的多视角判断，交付可阅读长文与简短结论。按用户指定执行路线；真实多角色执行和单模型角色模拟分别标记、分别验收。

## 模式与首次接入

- 主要输入仍是一条或多条文章链接。开始时先按 [读者背景](references/reader-profile.md) 读取已保存的职位与当前工作；首次缺少背景时提供一次可跳过的填写入口。已保存后每次复用，不反复问卷。读者背景不改变执行路线或写入授权。
- 默认围读：完成判断与报告，不强迫用户答题。
- 用户说“学会模式 / 带我学会 / 学会这篇”：读 [学习协议](references/learning.md)。已有报告先复用，不为进入学习重复派工；没有报告时可先围读，也可按用户要求直接围绕原文学习。
- 首次在新环境使用：读 [接入说明](references/onboarding.md)，确认可用路线和权限。未配置 Pilot 不等于不能围读；可提出本地隔离角色执行或单模型模拟，由用户确认。不得把替代路线冒称 AG CREW 原班角色。
- 缺少已有角色协议时：读 [可移植围读协议](references/reading-protocol.md)，用其中的通用视角作为明确标记的备选，不声称复刻历史 AG CREW。
- 改动或分发前：按 [验收场景](references/evaluation.md) 检查关键行为；结构校验和行为验证分别报告。

## 接单与路由

1. 提取文章 URL、顺序、研究问题、用户当前项目背景、执行路线、写回目标与已有 task_id。续接先读任务回执，不重复派工。
2. 用户说“AG CREW / Pilot 围读”时走真实 Pilot 路线。用户要求 Cohub 时复用相关 Space/session；要求两路时分别推进和验收。单模型模拟需用户已接受该模式，不能自动替代真实 crew。
3. 若存在私有文件 `references/local-routing.md`，可读取本机入口、既有成功样本和历史授权。该文件不随分发包交付；缺少它时使用接入说明，不能照搬原作者身份、UID 或账号。
4. 单篇独立建 case；多篇默认逐篇完成。要求 Roam 写回时，一篇写回并验证后再进入下一篇。只有用户明确要求联合围读才合并材料。

## 执行与取证

每篇下发稳定 task_id，带原始链接、最小背景和问题。要求执行者保留：

- 原文标题、URL、抓取时间、正文或可验证摘录、不可读部分；区分原文事实、作者自报、外部核验和推论。
- 首轮各角色原始判断；角色规则来自已有 AG CREW/Space 协议，不临时编一套替代。
- 碰撞须回应其他角色的具体判断，说明同意/反对/修正及改变判断的条件。
- 综合报告保留共识、实质分歧、啊哈、项目增量、证据限制和下一步验证；建议不自动成为实施指令。
- 执行模式、角色执行回执、报告位置、未完成项。文件数量或五个角色标题不能证明独立执行。

真实隔离执行需逐角色运行/回执证据。Cohub 同上下文角色扮演必须标为“Cohub角色模拟围读（单模型，非Pilot真实多角色crew）”，记录 `execution_mode: single-model-role-simulation`、`independence: not_guaranteed`。

两路独立研究时，首轮不互传另一条路线的结论；双方完成后再比较。

## 回执与恢复

- `fired`/`queued` 只代表提交或排队；`completed` 只代表一轮执行结束。还需核验来源、角色证据和实际报告。
- `capture` 无返回、机器 last-seen 更新、inbox 为空，都不能单独证明远端未消费、离线或卡在审批。
- SSO/Ferry 和机器令牌分开检查。过期的人类 SSO 不能直接解释 relay 故障；按当前 CLI 帮助确认能力。
- 重试查询前保留原 task/turn ID；提交结果不明时先查旧任务，不能重新创建任务碰碰运气。
- 预检失败可作一次有针对性的恢复/复查；持续无回执则保存 `submitted_unverified` 或具体阻塞并收口，不无限轮询。取消本地等待不等于取消远端任务。
- 仅当 capture 实际显示审批内容时评估其命令是否在授权范围内；不要盲发 `pane-send 1`。不得代替用户绕过安全审批。

## 交付与 Roam

每篇正文稳定保留“对你当前工作的意义”部分，按读者背景协议连接职位与具体工作；未提供背景时说明尚不能定制，不虚构身份或强行关联。

写读者正文前读取 [编辑与表达](references/editorial.md)。以文章特有的问题和判断组织正文，不把角色名、证据表和状态字段当成文章骨架；首轮记录仍保留，不能用润色代替真实碰撞。

先保留可迁移 Markdown 长文和证据位置，再按用户要求写回。已有明确写入授权不重复询问；没有写入要求则只交报告。

写 Roam 时使用当前环境已授权的写入工具；若已有统一写层则复用，不要求安装任何特定私人 Skill。用户指定父块时只追加该处；查重、固定 UID、写后核对内容及父子归属。超时后先读取原 UID，再补缺失项，避免重复。

默认保留完整围读报告，结构参考可移植围读协议；用户指定成功样本时优先读取并沿用，不擅自压缩成任务回执。只有用户要求短记录时，才交可读标题与原文链接、一句判断、2–4 条证据/分歧/项目建议、长文入口、执行模式。执行入口和长文产物分别给出，不能仅留一个 session 链接当长文。没有 Roam 工具或权限时交付可导入的嵌套列表 Markdown，并明确未写入。

## 反思与成长

每个 case 可保留局部 reflection：哪条初始判断改变了、由什么证据或碰撞导致、仍缺什么。所谓“出神”在此只指跨材料联系与重新审视，必须区分有证据的发现和待验证猜想，不编造顿悟，也不把角色拟人化描述当执行证据。

压缩记录保留结论、分歧、证据定位、改判条件和未决问题，并链接原始记录；不覆盖原文与首轮记录。重复案例支持的经验可列为候选规则，注明适用边界、反例和验证方法；只有明确授权后才修改共享协议、长期记忆或发布主页。不把普通围读授权解释为后台持续运行。

分别记录 `reading_status`、`learning_status`、`application_status`；报告完成不等于用户理解，理解不等于实际应用。学习过程持久化需用户要求，不默认建立个人能力档案。

真实 Pilot 结果与 Cohub 模拟结果分别记录。Roam 写回成功不代表站点已更新；发布、自动调度、长期记忆晋升、项目改造仅在任务包含这些要求时执行。

## 完成记录

在既有任务回执文件更新当前状态，保留每篇：`task_id`、URL、route、session/turn/remote ID、execution_mode、来源与角色证据、报告路径、Roam 父块/根块 UID、回读证据、未完成项和恢复动作。

最终面向用户说明实际完成了哪一路、结论在哪里、写回是否验证，以及仍缺什么。不要把模拟、排队、发布或写入这几种状态混为“围读完成”。
