# 读者背景：首次填写，之后复用

## 入口

文章链接是主输入，不要求用户每次再写背景。首次未配置时，先提供这一段简短入口，取材可同时继续，不因用户未回答而无限等待：

> 为了让解读与你有关，可以补充：
> - 职位或主要职责：
> - 最近主要在做的事情（1–3 项）：
> - 最关心的问题或约束（选填）：
> 选择：保存到本机供以后复用 / 仅本次使用 / 跳过。
> 不必填写姓名、公司名、客户名或其他机密。

用户说“记住，以后都用”才持久保存；只给出背景而未选择时，仅用于本次。已有用户明确确认的背景可复用，不从目录名、账号或聊天片段猜职位。跳过时照常围读，不强迫完成配置。

## 存储与生命周期

优先使用宿主已有的当前用户私有配置目录；标准本地回退为：

`$XDG_CONFIG_HOME/ag-crew-reading/reader-profile.json`，未设置 XDG_CONFIG_HOME 时使用 `~/.config/ag-crew-reading/reader-profile.json`。

用文件工具和标准 JSON 序列化保存，配置目录仅当前用户可访问，文件权限尽可能设为 0600。不得放进 Skill 文件夹、共享仓库或案例目录。写后回读字段确认保存成功；无文件权限时明确“仅本次，未保存”，不声称下次会记住。无本地存储的宿主可让用户每次附上背景，不假装跨会话持久化。

共享机器或多人工作区必须先由宿主确认当前用户隔离；无法确定时不加载已有档案，使用会话背景。单用户配置不可借用作多用户共享资料库。

建议结构（实际内容由用户提供；以下仅为格式说明，不是已存在的用户档案）：

```json
{
  "schema_version": 1,
  "role": "<用户填写的职位或职责>",
  "current_work": ["<用户填写的当前事项>"],
  "focus": ["<选填关注问题>"],
  "updated_at": "<保存时的 ISO 8601 时间>"
}
```

每次启动先读配置，用户当次要求优先于保存值。“这次按另一个角色”只临时覆盖；“以后改为/更新我的背景”才更新，保留未要求修改的字段。工作背景与当前任务明显冲突时简短确认，不反复要求全部重填。用户要求删除时只删除该配置并确认，不删除报告或其他文件；已交付报告不会自动被擦除。

## 固定读者视角

正文保留“对你当前工作的意义”，自然写成段落，覆盖有材料支持的内容：

- 文章中的哪个具体机制或论点与当前职责/工作有关。
- 它改变了什么决策，或解释了正在遇到的哪个问题。
- 适用条件、不能照搬之处，以及一个规模合适的下一步验证。

这是额外的读者视角，不替代论证、实现、风险等其他视角，不应迎合职位立场或扭曲原文。缺职位或工作信息时只用已知部分，并说明缺口；全部缺失时写“尚未提供工作背景，本节暂不作个人化判断”，可以附材料本身适用的人群。无关联时明确说明，不强凑建议。

开启学会模式时优先从当前工作中选择迁移题，但只用用户明确提供的背景，不编造实际业务数据。

## 隐私与远端派工

保存背景不等于允许上传全部档案。远端只传任务必需且已获准的概括；涉及内部事项时先在本地抽象化，无法判断可否传输则让用户确认或在本地补写个性化部分。不得上传配置文件或凭据。

分发包只含这份协议，不含实际档案。公开示例默认使用明确标记的虚构背景；私人报告可用真实背景，但公开或分享前单独检查并脱敏。删除配置不撤回已发给远端的内容。
