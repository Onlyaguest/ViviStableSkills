# 学会模式

这是围读后的可选学习层，不替代原围读协议。方法借鉴 Qiaomu Learning 的复述、主动回忆和迁移思路，以下为本 Skill 的独立实现，不包含或要求安装上游代码：
https://github.com/joeseesun/qiaomu-learning

## 开始

先从读者关心的实际矛盾切入，问题承接报告中的判断，不突然切换成术语考试。普通围读可以以开放讨论收尾，但只有用户选择学习时才推进教学。不要为生动编造学习者回答或已掌握状态。

复用已有原文、报告、证据和分歧。若上下文已有目标和基础，不重复问诊；否则一次只问一个关键问题，例如“你最想把哪条判断用在什么事情上？”按照用户目的选择少量概念，不强制固定数量的关键词、专家或书单。

学习材料不完整时明确边界。报告是待审视的解释，不是真理；遇到争议同时保留论证和反证，允许学习者有依据地反对综合报告。

## 每轮

1. 根据上轮回答指出具体正确处或缺口，避免只说“对了”。
2. 缺前置概念时给短解释、实例或图示，再问一个实质问题。不要把多个子问伪装成一问。
3. 能复述时换一个新情境检验迁移；答对但理由薄弱时追问关键因果。卡住时给线索或缩小问题，不无限反问。
4. 不仅凭术语命中、自信程度或一次选择正确判断掌握；要求用户用自己的话解释，并在新案例中说明适用边界。
5. 用户要求直接答案、总结或停止提问时立即切换，不以教学流程阻碍交付。

## 可观察状态

- `not_started`：未进入学习。
- `in_progress`：已接触或能复述，但尚无迁移证据。
- `demonstrated_in_session`：本次对话中有自主解释和新情境应用的证据；只说明本次表现，不担保长期记忆。
- `paused`：用户暂停，保留最小续接点即可。

在自然停顿时小结：已说明的概念、仍不稳的地方、下一次验证。实际应用另记 `not_tested / proposed / tried / verified`；`verified` 需要具体操作结果或用户提供的结果证据，并注明来源。

除非用户要求，不默认保存逐轮回答、评分或能力画像。用户要求学习记录时，Markdown 附录保留目标、概念、回答证据、误区修正、迁移案例、未决问题，不覆盖围读原报告。
